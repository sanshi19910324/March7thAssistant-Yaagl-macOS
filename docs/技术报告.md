### 2.2 自动化脚本（已验证可用）

**文件：`/tmp/watch_start.sh`**

```bash
#!/bin/bash
IFACE="en1"; LOG=/tmp/watch_start.log
exec >> "$LOG" 2>&1
echo "=== $(date '+%H:%M:%S') 监视启动 ==="
# 最多等 180 秒
for i in $(seq 1 180); do
  if pgrep -f "StarRail.exe" > /dev/null 2>&1; then
    echo "$(date '+%H:%M:%S') 检测到游戏进程，立即断网"
    sudo -n /sbin/ifconfig "$IFACE" down
    sleep 120                    # ★ 关键：120 秒
    echo "$(date '+%H:%M:%S') 恢复网络"
    sudo -n /sbin/ifconfig "$IFACE" up
    sudo -n /usr/sbin/ipconfig set "$IFACE" DHCP 2>/dev/null
    sleep 4
    echo "$(date '+%H:%M:%S') ip=$(/sbin/ifconfig $IFACE | grep 'inet ' | awk '{print $2}')"
    echo "=== END ==="
    exit 0
  fi
  sleep 1
done
echo "$(date '+%H:%M:%S') 超时未检测到游戏"
```

**执行方式**：
```bash
nohup sudo -n -u "$(whoami)" /bin/bash /tmp/watch_start.sh > /dev/null 2>&1 &
# 然后手动点「开始游戏」
```

## 四、踩过的坑与解决方案（完整记录）

### 坑 1：启动器不识别已安装游戏（yaagl #780）

**现象**：游戏文件 107G 完整、MD5 全对，但启动器永远显示「下载」按钮。

**根因**（GitHub #780 用户 yudonglin 分析）：
HoYo 国服 `game_scan_info` 里 `StarRail.exe` 的 MD5 是 `18ed4ed868aefd5dad48a5b2c978cbb2`，而 4.6.0 manifest 和本地实际文件都是 `c2d5d1415718c3c8684f5bd47a38e77d`——**哈希不匹配**，导致 sophon 无法判定已装版本。

**解决**：回滚到 0.3.21（从 `StarRail_Data/data.unity3d` 读版本，不走 exe 哈希）
```bash
# 关键：只换 app 不够，必须同时替换 resources.neu
cp /tmp/resources_hkrpgcn_0321.neu \
   ~/Library/Application\ Support/Yaagl\ HSR/resources.neu
```

### 坑 2：`initDriver Failed: Error [4,1114,0]`（反作弊拦截）

**现象**：点开始游戏 → 黑窗几秒消失 / 纯黑无响应。

**错误链**：
```
err:service:validate_context_handle Access denied
err:module:import_dll Library WDFLDR.SYS (which is needed by HoYoKProtect.sys) not found
err:ntoskrnl:ZwLoadDriver failed: c0000142
→ initDriver Failed: Error [4,1114,0]
```

**根因**：Wine 不实现 Windows 内核驱动子系统，`WDFLDR.SYS` 全系统不存在。

**GitHub 结论**（#551 官方置顶）：
> 「**THERE IS NO FIX FOR THIS PROBLEM AS OF NOW.**」

**解决**：**断网 120 秒**（本报告核心突破）

### 坑 3：hosts 阻断导致反作弊失败（#706）

**现象**：清理 hosts 前的 7 条阻断导致同样报 `initDriver Failed`。

**解决**：彻底清理所有 `0.0.0.0 <mihoyo/hoyoverse 域名>` 条目 + 刷新 DNS
```bash
sudo python3 -c "
import re
p='/etc/hosts'
lines=open(p).read().split('\n')
kept=[l for l in lines if not re.match(r'^\s*0\.0\.0\.0\s+\S*(mihoyo|hoyoverse|juequling)', l)]
open(p,'w').write('\n'.join(kept))
"
sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
```

### 坑 4：Tailscale DNS 拦截

**现象**：断网恢复后 `hkrpg.hoyoverse.com` 解析失败（NXDOMAIN）。

**根因**：Tailscale 的 DNS（`100.100.100.100`，order 100400）优先级高于本地网络（order 200000）。

**解决**：给 Ethernet 设置公共 DNS
```bash
sudo networksetup -setdnsservers Ethernet 223.5.5.5 119.29.29.29
```

### 坑 5：Yaagl 首次配置需要管理员权限

**现象**：`open -g` 后台启动时，授权弹窗被遮挡，进度条卡死 20 分钟。

**根因**：Yaagl 需要 `xattr -s -r -d com.apple.quarantine` 且要 administrator privileges。

**解决**：**前台启动**（不要用 `-g`），或在弹窗出现时手动输密码。

### 坑 6：WebView 按钮点不动

**现象**：CGEvent / cliclick / AppleScript 都无法点击「推荐设置」「开始游戏」等按钮。

**根因**：Yaagl 用 neutralinojs WebView 渲染，合成鼠标事件进不去。

**解决**：**需要用户手动点击**（这部分无法自动化）。

### 坑 7：绕过启动器直启游戏失败

**现象**：直接 `wine StarRail.exe` 报 `Failed to initialize graphics`。

**根因**：启动器负责注入 DXMT DLL（d3d11.dll/dxgi.dll 等）到 wineprefix，还设置一系列 DXMT 环境变量。手动启动缺这些。

**解决**：**必须通过启动器启动**，不要绕过。

## 一、攻克的技术难题（9 处）

### 问题 1：截图含标题栏，尺寸 1920x1112

Wine 窗口含 32px 标题栏，M7A 假设 1920x1080，导致所有坐标偏移。

```python
h, w = bgr.shape[:2]
if h > w * 9 / 16:
    title_bar = h - int(w * 9 / 16)
    if 0 < title_bar < h // 4:
        bgr = bgr[title_bar:, :]     # 裁掉标题栏
```

### 问题 2（核心）：点击落点偏移到隔壁按钮 ⭐

**现象**：点「指南」却进了「联机玩法」。

**根因**：桥用 `MOUSEEVENTF_ABSOLUTE` 的 0-65535 归一化，映射到**整个 Windows 虚拟桌面**，而游戏窗口在桌面有偏移（320,161），导致点击整体漂移。

**修复**（`tools/m7a_wine_bridge.py`）：
```python
def client_to_screen(client_x, client_y, hwnd=None):
    """客户区坐标 → 屏幕坐标"""
    if not hwnd:
        hwnd = GetForegroundWindow()
    pt = wt.POINT(int(client_x), int(client_y))
    if ClientToScreen(hwnd, ctypes.byref(pt)):
        return pt.x, pt.y
    return client_x, client_y

# 点击时按真实桌面尺寸归一化
sx, sy = client_to_screen(x, y, hwnd)
dw = GetSystemMetrics(SM_CXSCREEN)
dh = GetSystemMetrics(SM_CYSCREEN)
nx = int(sx * 65535 / dw)
ny = int(sy * 65535 / dh)
```

### 问题 3：Wine 窗口失焦后吞掉输入

**修复**：新增 `ensure_focus(hwnd)`，每次输入前检查并恢复焦点：
```python
def ensure_focus(hwnd):
    if GetForegroundWindow() != hwnd:
        ShowWindow(hwnd, SW_RESTORE)
        BringWindowToTop(hwnd)
        SetForegroundWindow(hwnd)
        SetFocus(hwnd)
```

### 问题 4：`switch_to_game()` 抢自己的焦点

原代码用 osascript 把 **Python 进程**设为前台，反而抢走游戏焦点。

**修复**：删掉 osascript，改用标题注册窗口：
```python
title = self.cfg.get_value("game_title_name", "崩坏：星穹铁道")
self.client.set_foreground(pid, title=title)
```

### 问题 5（核心）：输入完全静默丢弃 ⭐

**现象**：M7A 跑了但桥收不到任何输入命令（`command=3` 不增加）。

**根因**：`auto` 的 `input_handler` 在**模块导入时**绑定，那时 cfg 未加载完 → 拿到 `LocalInput`（Windows 专用）而非 Yaagl 桥。

**修复**（`module/automation/automation.py`）：改为延迟解析
```python
@property
def input_handler(self):
    if self._input_handler is None:
        self._input_handler = get_game_controller().get_input_handler()
    return self._input_handler
```

**修复**：恢复自动连接 + `_connecting` 重入保护：
```python
if self._sock is None:
    if self._connecting:
        return None
    if not self.connect():
        return None
```

### 问题 7（核心）：带 alpha 通道的模板全部匹配失败 ⭐

**现象**：`guide.png` 匹配分数 `116931`，阈值 `0.9`，永远失败。我一度误以为是 `2000000` 阈值是 bug，改成 0.9 后反而匹配到错误位置。

**真正根因**：`image_utils.py` 对带 mask 的模板用 `TM_SQDIFF`（**未归一化**，值越小越好），但阈值是按 0-1 写的。上游注释也承认：「部分文件识别设置阈值要设置的很大很大（如域锚点要 3,000,000）」。

**根治**（`utils/image_utils.py`）：改用归一化 SQDIFF 并转成相似度
```python
if mask is not None:
    result = cv2.matchTemplate(screenshot, template, cv2.TM_SQDIFF_NORMED, mask=mask)
    min_val, _, min_loc, _ = cv2.minMaxLoc(result)
    score = 1.0 - float(min_val)          # 0..1，越大越好
    return max(0.0, min(1.0, score)), min_loc
```
同时把 `automation.py` 的比较逻辑统一为 `matchVal >= threshold`。

# 第十三部分：守护进程两次致命 Bug 与修复

## Bug 1：启动器 Fatal error（winedrv_config.bat exit 1）

**现象**：点「开始游戏」弹出 Fatal error，`Command return non-zero code (1)`，StdErr 为空。

**真正原因**：不是 `wineserver`，而是 **`winedevice.exe`** 占用 wineprefix。

排查过程：
1. 手动执行 bat → 成功（exit 0），说明 bat 本身没问题
2. 杀 wineserver 后仍报错 → 排除 wineserver
3. `pgrep -fl wine` 发现 **5 个 winedevice.exe 残留**（PID 9440/9446/68441/68451/86007）
4. 全部杀掉后，启动器恢复正常

**关键认知**：`winedevice.exe` 是 Wine 的设备驱动宿主进程，
它会持有 wineprefix，只有它退出 prefix 才真正释放。

**修复**：清理范围扩到整个进程组
```python
for pat in ("winedevice", "plugplay", "services.exe", "wineserver"):
    run(f"pkill -9 -f {pat}")
```
并加启动预清理：守护启动时若发现残留先清掉。

## Bug 2（更严重）：游戏刚进就卡死，日志刷到 1.9GB

**现象**：点开始游戏、断网 120 秒、恢复网络都正常，但游戏窗口一出现就卡死。

**日志特征**：
```
msync: up and running.
err:module:import_dll Library WDFLDR.SYS ... not found     ← 反作弊（已绕过，正常）
err:sync:server_register_wait Failed to send server register wait: 0x10000003
  ↑ 5187+ 条，每秒几千条，日志 1.9GB
```

`0x10000003` = `STATUS_INVALID_INFO_CLASS`，表示线程向另一个线程注册等待时，
**接收方线程已经不在了** —— msync 通信管道断裂。

**根因（我的错误）**：为修 Bug 1，把 `kill_bridge` 改成杀全部 wine 进程。
而守护在「游戏窗口出现」时调用它来重启桥：

```python
log("游戏窗口已出现，重启桥")
kill_bridge()      # ← 杀了 winedevice/services.exe，游戏正依赖它们
start_bridge()
```

游戏启动过程中这些进程被 `pkill -9`，msync 立刻崩溃 → 疯狂刷错误 → 卡死。

**修复**：拆成两档清理，严格区分场景

| 函数 | 杀什么 | 只能用于 |
|---|---|---|
| `kill_bridge_only()` | 只杀 `m7a_wine_bridge` | **游戏运行中**（窗口出现后起桥、桥失联重启） |
| `kill_bridge()` | 桥 + winedevice + plugplay + services + wineserver | **游戏未运行**（启动预清理、游戏退出后收尾） |

调用点分配（最终版）：
```
行143  kill_bridge()        启动预清理（游戏未跑）
行154  kill_bridge_only()   启动时游戏已在跑
行193  kill_bridge_only()   窗口出现后起桥
行198  kill_bridge_only()   等窗口超时起桥
行206  kill_bridge()        游戏退出后收尾
```

## 附带修复：日志无限增长

守护日志加 2MB 上限，超了保留最后 500 行。

## 核心技术结论

**在 Wine 环境里，「重启桥」和「清理 prefix」是两件性质完全不同的事：**

- 重启桥 = 只杀桥进程（Python 侧）
- 清理 prefix = 杀 winedevice/wineserver（Wine 侧）

混用会直接杀死正在运行的游戏。这是本次最大的坑。
