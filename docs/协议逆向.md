### 证据 A：请求构造机器码（VA 0x1400038a7，.text 节内）

逐条指令验证（12/12 命中）：

| 文件偏移 | 机器码 | 指令 | 语义 |
|---|---|---|---|
| +0x1a | `c7 44 24 20 42 47 49 31` | `mov dword [rsp+0x20], 0x31494742` | **+0x00 magic = "BGI1"** |
| +0x35 | `66 89 4c 24 24` | `mov [rsp+0x24], cx` | **+0x04 flag = 5** |
| +0x0a | `66 89 44 24 26` | `mov [rsp+0x26], ax` | **+0x06 command**（源 `[rdx+6]`） |

### 证据 B：`send_response` 完整反编译（VA 0x1400015de）

```c
undefined8 send_response(SOCKET s, longlong req_hdr, undefined4 status, char *payload, uint len) {
  char local_48[6];       // +0x00..0x05
  undefined2 local_42;    // +0x06..0x07
  undefined4 local_40;    // +0x08..0x0B
  uint   local_3c;        // +0x0C..0x0F
  undefined4 local_38;    // +0x10..0x13
  undefined4 local_34;    // +0x14..0x17

  local_42 = *(undefined2 *)(req_hdr + 6);   // +0x06 command  ← 回显请求
  local_40 = *(undefined4 *)(req_hdr + 8);   // +0x08 字段     ← 回显请求
  builtin_strncpy(local_48, "BGI1\x05", 6);  // ★ 字面量直书: magic "BGI1" + flag 0x05
  local_3c = param_5;                         // +0x0C payload 长度
  local_38 = param_3;                         // +0x10 status
  local_34 = 0;                               // +0x14 reserved
  // 先 send 24 字节头，再 send payload（两段式，循环保证全部发出）
}
```

**⇒ 两条独立证据（机器码 + 反编译源码）完全吻合，头部结构定案：**

| 偏移 | 类型 | 字段 | 请求侧取值 | 响应侧取值 |
|---|---|---|---|---|
| 0x00 | int | **magic** | `0x31494742`（小端 = ASCII `BGI1`） | 同 |
| 0x04 | short | **flag** | **必须 5** | 固定 5 |
| 0x06 | ushort | **command** | 命令字 | 回显请求 |
| 0x08 | uint | 未命名 | 源值（来源未定） | 回显请求 |
| 0x0C | uint | **payload 长度** | ≤ `0x10000` | 响应 payload 长度 |
| 0x10 | uint | 未命名 | r8d | **status** |
| 0x14 | int | **reserved** | **必须 0** | 0 |
| 合计 | | **24 (0x18) 字节** | | |

**校验与错误码**（反编译 L232-240）：
```c
if (magic != 0x31494742 || payload_len > 0x10000 || reserved != 0)
    send_response(..., status=1, ...), break;     // 魔数/长度/保留字非法
if (flag != 5)
    send_response(..., status=2, ...), break;     // 标志位非法
```

## 三、认证算法（命令 2）—— 已完整还原

反编译 L264-292：

```c
// local_2ee = 环境变量 BETTERGI_WINE_BRIDGE_TOKEN 的值
// _Memory  = 收到的 payload
if (!already_authenticated) {
    size_t toklen = strlen(token);
    uint acc = payload_len ^ (uint)toklen;
    size_t n = (toklen <= payload_len) ? payload_len : toklen;
    for (size_t i = 0; i < n; i++) {
        uint a = (i < payload_len) ? payload[i] : 0;
        uint b = (i < toklen)     ? token[i]   : 0;
        acc |= (a ^ b);
    }
    if ((char)acc == 0) {           // 逐字节全等（且长度一致）
        already_authenticated = 1;
        fwrite("client authenticated\n", ...);
    } else { status = 5; }          // 认证失败
} else { status = 6; }              // 已认证
```
**本质**：把 payload 与 token 补齐后逐字节 XOR，再 OR 归约；全 0 即相等。等价于「payload == token」。

## 六、`input-context wake` 机制（Wine 特有补偿）

日志字符串锚点（`rea search "input-context"` 取得 10 处地址）：

```
input-context policy enabled=%d wakeButton=%u wakeTimeoutMs=%u
input-context priming submitted
input-context prepare ready=%d foreground=0x%llx target=0x%llx
input-context wake started timeoutMs=%u foreground=0x%llx target=0x%llx
input-context wake cursor move submitted client=(%ld,%ld) screen=(%ld,%ld)
input-context click probe positioned button=%u screen=(%ld,%ld)
input-context click probe blocked: target client center is unsafe
input-context wake ready elapsedMs=%llu primes=%u firstPrimeResult=%d foreground=0x%llx
input-context wake timed out elapsedMs=%llu primes=%u firstPrimeResult=%d foreground=0x%llx
input-context wake settled best-effort elapsedMs=%llu mousePrimes=%u inputProbes=%u ...
```

**语义**：发真实输入前先做「唤醒」——探测点击（校验点击点落在目标客户区内，`wake_point_is_safe`）→ 检查前台窗口 → 重试 → 超时降级为 best-effort。
**说明**：Wine 窗口存在「失焦后首次输入被吞」的真实问题，这是被验证过的必要补偿。

## 十、逆向方法论（可复用）

```
1. rea analyze <pe>                              → Ghidra 自动分析，拿 evidence_id
2. rea search <pe> "<诊断日志字符串>" --format json → 得字符串地址（开发者日志是最好的锚点）
3. rea xrefs <pe> <字符串地址>                    → 定位引用函数入口
4. rea decompile <pe> <函数地址>                  → 完整 C 反编译
5. rea read-bytes <pe> <地址> --length N          → 读机器码验证立即数（比反编译更硬）
6. 在反编译里 grep recv/send/SendInput/GetEnvironmentVariable → 还原协议与认证
7. 用 PE 节表把 file offset → RVA → VA 换算，确认代码归属函数
```

**关键经验**：
- **诊断日志字符串是最好的逆向入口**——开发者写的高信息量日志（`input-context wake started ...`）直接暴露内部状态机
- **机器码验证优于反编译**：`c7 44 24 20 42 47 49 31` 这种立即数指令是铁证，反编译的变量命名可能误导
- **双向验证**：请求构造（机器码）与响应构造（源码）交叉核对，字段偏移才敢定案
- Ghidra 只识别「定义的字符串」数据，立即数形式的 `BGI1` 搜不到，必须用 `read_bytes` 找字节模式
